# אוטומציית ניהול לידים — קליניקה אסתטית

מימוש מלא של תוכנית האוטומציה: קליטה מוואטסאפ/אינסטגרם/טופס, בדיקת תקינות,
מניעת כפילויות, סיווג AI עם ניתוב מחייב לאדם, מעקב אוטומטי וקביעת תור.

כל הלוגיקה יושבת ב-`lib/` כפונקציות **טהורות** שמחזירות רשימת פעולות ולא
מדברות עם אף שירות. `scripts/build.mjs` מטמיע את אותו קוד בתוך ה-workflows של
n8n. כך יש מקור אמת אחד, והכול נבדק ב-`node --test` בלי webhooks ובלי חשבון.

```
lib/        הלוגיקה (מקור האמת)
n8n/        שלושה workflows מוכנים לייבוא — נוצרים אוטומטית מ-lib/
prompts/    פרומפט הסיווג — נוצר אוטומטית מ-lib/classify.js
sheets/     מבנה הגיליון — נוצר אוטומטית מ-lib/record.js
test/       40 בדיקות, כולל הרצה של הקוד המוטמע ב-n8n
scripts/    הבנייה
```

## הרצה

```bash
npm test               # כל הבדיקות
npm run build:automation   # בנייה מחדש של n8n/, prompts/ ו-sheets/
```

הבדיקות נכשלות אם תוצר ב-git אינו תואם לקוד — כלומר אי אפשר לשנות לוגיקה
ולשכוח לבנות מחדש.

## שדות וסטטוסים

מבנה הגיליון המלא: [`sheets/schema.md`](sheets/schema.md), שורת כותרות מוכנה
להדבקה: [`sheets/headers.csv`](sheets/headers.csv).

מעבר לשדות שהוגדרו בתוכנית נוספו שש עמודות תפעוליות: דחיפות, סיבות הסלמה,
ביטחון סיווג, מזהה בערוץ, מזהה הודעה אחרונה (מונע עיבוד כפול של אותו webhook),
היסטוריה בעייתית, ושתי עמודות לתזכורת התור.

```
חדש → נוצר קשר → ממתין לתשובה → נקבע תור / לא רלוונטי / הועבר לאדם
```

המעברים החוקיים מוגדרים ב-`lib/statuses.js`, כולל פתיחה מחדש של ליד שנסגר
כשהוא פונה שוב.

## הטריגרים ומה הם מפעילים

| טריגר | Workflow | קובץ |
| ----- | -------- | ---- |
| וואטסאפ (Meta Cloud API או Twilio) | קליטה | `n8n/clinic-leads-intake.json` |
| אינסטגרם — הודעה פרטית או תגובה | קליטה | אותו workflow, אותו webhook |
| טופס באתר | קליטה | אותו workflow, אותו webhook |
| כל שעה — סריקת מועדי מעקב | מעקב | `n8n/clinic-leads-followup.json` |
| שינוי שורה בגיליון (`נקבע תור`) | קביעת תור | `n8n/clinic-leads-appointment.json` |

שלושת המקורות נכנסים ל-webhook אחד. `detectSource()` מזהה את המבנה
(`whatsapp_business_account`, `instagram`, `MessageSid` של Twilio, או טופס)
ו-`normalizeInbound()` מחזיר מבנה אחיד אחד.

## סדר הפעולות והיכן הוא ממומש

| # | שלב | קוד |
| - | --- | --- |
| 1 | קליטה ואיחוד מבנה | `lib/normalize.js` |
| 2 | בדיקת תקינות וספאם | `lib/validate.js` |
| 3 | בדיקת כפילות לפי מפתח | `lib/pipeline.js` → `updateExisting()` |
| 4 | סיווג AI + כללי הסלמה | `lib/classify.js` |
| 5 | יצירת רשומה | `lib/record.js` → `buildLeadRecord()` |
| 6 | תגובה ראשונית ועדכון סטטוס | `lib/pipeline.js` → `createNew()`, `lib/messages.js` |
| 7 | התראה למזכירה | `lib/messages.js` |
| 8 | מעקב 24 שעות, 2 ניסיונות | `lib/followup.js` → `planFollowup()` |
| 9 | קביעת תור, אישור ותזכורת | `lib/followup.js` → `planAppointmentBooked()` |

`processInbound()` מחזיר רשימת פעולות אחת מסוג `create_record` / `update_record` /
`send_message` / `notify_staff`. n8n רק מבצע אותן — אין לוגיקה מפוזרת בין nodes.

## הכלל שמגן על הקליניקה

ה-AI ממיין, מסכם ומנסח — לא מייעץ. זה לא נשען על הפרומפט בלבד:
`resolveClassification()` מריץ כללים דטרמיניסטיים **מעל** תשובת המודל.

מועבר לאדם (`הועבר לאדם` + התראה מיידית, וללקוח נשלח רק "מישהו מהצוות יחזור
אליך בהקדם"):

| סיבה | מה מזהה |
| ---- | ------- |
| `medical` | הריון/הנקה, תרופות, תופעות לוואי, מחלות רקע, "מתאים לי?", "בטוח?" |
| `complaint` | תלונה או חוסר שביעות רצון מטיפול קודם |
| `price_negotiation` | הנחה, "יקר מדי", משא ומתן, תשלומים |
| `cancellation_refund` | ביטול, החזר כספי, זיכוי |
| `problematic_history` | דגל ברשומה הקיימת של אותו לקוח |
| `low_confidence` | ביטחון מתחת ל-0.7, או פלט שאינו JSON תקין |

גם אם המודל יחזיר `requiresHuman: false`, מילה כמו "בהריון" מעבירה את הליד
לאדם. בדיקה שמכסה בדיוק את זה: `test/classify.test.js`.

בכל התבניות ב-`lib/messages.js` אין מחיר, אין מידע רפואי ואין הבטחת תוצאה.

## הגדרה

1. **גיליון** — הדביקו את `sheets/headers.csv` בשורה 1. אל תשנו את שם או מיקום
   העמודה `מפתח ליד`; כל העדכונים מותאמים לפיה.
2. **ייבוא** — ב-n8n: Import from File לכל אחד משלושת הקבצים ב-`n8n/`.
3. **Credentials** — Google Sheets OAuth2 לכל ה-nodes של הגיליון, ו-Header Auth
   ל-nodes של Meta Graph (`Authorization: Bearer <token>`) ושל Gemini
   (`x-goog-api-key: <key>`).
4. **משתני סביבה** ב-n8n:

| משתנה | לשם מה |
| ----- | ------ |
| `CLINIC_LEADS_SHEET_ID` | מזהה הגיליון |
| `CLINIC_LEADS_SHEET_NAME` | שם הלשונית (ברירת מחדל: `לידים`) |
| `CLINIC_LEADS_SHEET_URL` | קישור שנכנס להתראות למזכירה |
| `CLINIC_SECRETARY_PHONE` | היעד של כל ההתראות |
| `WHATSAPP_PHONE_NUMBER_ID` | מזהה השולח ב-WhatsApp Cloud API |
| `INSTAGRAM_USER_ID` | חשבון האינסטגרם העסקי |
| `CLINIC_AI_MODEL` | ברירת מחדל: `gemini-2.5-flash` |

   גישה ל-`$env` מתוך nodes דורשת `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`.
5. **חיבור המקורות** — הפנו את ה-webhooks של Meta/Twilio ואת הטופס באתר לכתובת
   `POST /webhook/clinic-leads`.

### Make.com

הלוגיקה לא תלויה ב-n8n. ב-Make בונים את אותו מבנה עם מודול Webhook, מודול
Google Sheets ו-HTTP, ומעתיקים את תוכן ה-Code nodes (הקוד המוטמע בקבצי ה-JSON,
או `lib/` בבנייה מקבילה) למודול אחד מסוג Tools → Run JavaScript.

## החלטות שהתוכנית לא הכריעה

1. **טלפון באינסטגרם** — ב-webhook של אינסטגרם אין טלפון. לכן טלפון הוא שדה
   חובה רק בוואטסאפ ובטופס (`CONFIG.phoneRequiredChannels`), ובאינסטגרם מפתח
   הליד הוא `instagram:<sender-id>` וההודעה הראשונה מבקשת מספר. כשהמספר מגיע
   הוא מושלם לרשומה הקיימת.
2. **שאלת מחיר רגילה** ("כמה עולה?") אינה מסלימה — ה-AI ממילא לא נוקב במחיר,
   וההתראה למזכירה מציינת שנשאלה שאלת מחיר. בקשת הנחה או משא ומתן כן מסלימה.
3. **לקוח שהגיב** מאפס את מונה הניסיונות ומחזיר את הסטטוס ל-`נוצר קשר`.
4. **ליד שנסגר כ"לא רלוונטי" ופנה שוב** נפתח מחדש עם התראה למזכירה, ולא נפתחת
   לו רשומה חדשה.
5. **תור שנקבע לפחות מ-24 שעות מראש** מקבל אישור בלבד, בלי תזכורת נפרדת.
6. **פנייה שנפסלה** נרשמת בגיליון כ-`לא רלוונטי` (לתיעוד) ואינה מקבלת מענה
   אוטומטי — רק התראה קצרה למזכירה.

## מה עוד נדרש לפני עלייה לאוויר

- אישור הנוסחים ורשימת הטיפולים (`TREATMENTS` ב-`lib/classify.js`) מול הקליניקה.
- חיבור ליומן התורים, אם רוצים שקביעת התור תגיע מהיומן ולא מסימון בגיליון.
- החלטה על שמירת תוכן הודעות של לקוחות — הגיליון שומר את הפנייה המקורית
  ואת ההערות, ויש להתאים זאת למדיניות הפרטיות של הקליניקה.
